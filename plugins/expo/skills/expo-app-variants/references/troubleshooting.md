# Troubleshooting app variants

## Symptom table

| Symptom                                                                     | Cause                                                                                                                                                                                 | Fix                                                                                                                                                                                                               |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Installing dev replaces production                                          | Identifiers still shared                                                                                                                                                              | `npx expo config --json \| jq '.ios.bundleIdentifier, .android.package'` under each variant. If they match, `getAppId()` is not being reached                                                                     |
| Right variant on `eas build`, wrong one on `expo start`                     | `eas.json` `env` is invisible to local commands                                                                                                                                       | Set the value in `.env.local`, or move to EAS environments and `eas env:pull`                                                                                                                                     |
| An update carried the wrong variant's config or values                      | `--environment` missing or not the channel's mapped environment. `eas update` never reads `eas.json` `env`, and with an environment set it ignores `.env` files                       | Pass `--environment` for the channel's mapped environment (identical names in the default setup), with `APP_VARIANT` set in that EAS environment                                                                  |
| `eas env:pull` wrote nothing useful                                         | No variable in that environment yet                                                                                                                                                   | `eas env:list --environment <env>` to confirm what exists                                                                                                                                                         |
| Everything from `app.json` disappeared                                      | `...config` not spread, or `app.config.ts` exports an object instead of a function                                                                                                    | Spread `...config` first; export a function                                                                                                                                                                       |
| Bundle id is right but other `ios` settings vanished                        | `...config.ios` not spread                                                                                                                                                            | `ios: { ...config.ios, bundleIdentifier: getAppId() }`                                                                                                                                                            |
| Plugins from `app.json` stopped applying                                    | `plugins` overwritten instead of appended                                                                                                                                             | `plugins: [...(config.plugins ?? []), ...]`                                                                                                                                                                       |
| QR code opens the wrong app                                                 | `addGeneratedScheme` not gated, or older variants built before the change                                                                                                             | Gate it, then rebuild or remove the other variants                                                                                                                                                                |
| Dev build shows the wrong variant name                                      | Dev server running under a different `APP_VARIANT`                                                                                                                                    | Match the server to the build. With EAS environments: `eas env:pull --environment development`, then restart                                                                                                      |
| `process.env.APP_VARIANT` is `undefined` in a component                     | No `EXPO_PUBLIC_` prefix, so it never reaches the JS bundle                                                                                                                           | App code rarely needs it — read the environment's `EXPO_PUBLIC_*` values instead. To print the variant in the app, add a parallel `EXPO_PUBLIC_APP_VARIANT` with the same value in each environment and read that |
| Identity did not change after switching variants                            | Native project on disk is stale                                                                                                                                                       | Set the variant in `.env.local` (or `eas env:pull` the matching environment), then `npx expo prebuild --clean`                                                                                                    |
| An EAS build carried another environment's values                           | The profile has no `environment` key, so EAS Build picked a default: `production` when `distribution` is `store`, `development` when `developmentClient` is true, otherwise `preview` | Set `environment` explicitly on every build profile                                                                                                                                                               |
| Every EAS build gets the dev identity although profiles set `environment`   | The referenced environments hold no `APP_VARIANT` variable, so the config falls to `default`                                                                                          | `eas env:list --environment <env>` to confirm, then `eas env:create` the missing variable in each environment                                                                                                     |
| A preview or production variant built locally still shows the dev menu      | `expo-dev-client` is embedded in every local debug build, and `npx expo run:*` builds debug by default                                                                                | Build that variant with the Release configuration (`run:ios --configuration Release`, `run:android --variant release`), or build it on EAS                                                                        |
| Push notifications or Maps broken on the dev variant                        | The new identifier has no registration                                                                                                                                                | The user registers each identifier in the service dashboard; then switch the per-variant file or key in `app.config.ts`, for example `android.googleServicesFile`. See Step 6                                     |
| A build or update fails because environment `staging` does not exist        | Only `development`, `preview`, and `production` exist by default; creating custom environments needs a Production or Enterprise plan                                                  | Point the variant's profile at a built-in environment, or create the environment on a plan that allows it                                                                                                         |
| A custom variant falls back to the dev identity                             | Its name is not a `case` in the helper, so it hits `default`                                                                                                                          | Add the `case` to each helper                                                                                                                                                                                     |
| Config broke after "setting up variants" on a project that already had them | The existing setup was replaced instead of extended                                                                                                                                   | Restore the previous config, then apply only the missing steps. See Step 0                                                                                                                                        |
| TypeScript error assigning `getIcon()` to `icon`                            | Return type includes `undefined`                                                                                                                                                      | `icon: icon ?? config.icon`                                                                                                                                                                                       |
| `TS2322: Types of property 'slug' are incompatible` on the default export   | `ConfigContext.config` is a `Partial<ExpoConfig>`, so `slug` is `string \| undefined`, but `ExpoConfig` requires it                                                                   | Add `slug: config.slug ?? "my-app"` after `...config`                                                                                                                                                             |

## Diagnosing with `expo config`

`npx expo config --json` is the single most useful check. It resolves `app.json` through `app.config.ts` exactly as Expo will, under whatever `APP_VARIANT` is set. Run the per-variant loop from the Verify section of `SKILL.md` — one distinct identity per variant means Step 1 is correct.

To catch a dropped spread, diff the resolved config before and after adding `app.config.ts`. Any key that disappears was lost to a missing spread.

## When a variant already shipped

Changing a production bundle identifier on an app that is already in the stores creates a **new** app, not an update. Existing users do not migrate.

So set the production identifier to the one already published, and give the new suffixes to dev and preview. That is what `getAppId()` returning the bare `APP_ID_PREFIX` for `production` does — production keeps the identity it already had.
